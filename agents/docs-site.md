# Docs Site

## Scope

The public documentation site in `site/`, published to GitHub Pages at
https://denex-io.github.io/denex-network-manager/.

Read this before changing anything under `site/`, or before adding user-facing documentation
anywhere.

## What this subsystem is

An Astro + Starlight static site. It is the **only** place long-form user documentation lives; it is
not a mirror of `README.md`.

- `site/astro.config.mjs` — Starlight config, sidebar, integrations
- `site/src/content/docs/**` — every page, as Markdown/MDX with frontmatter
- `site/src/content.config.ts` — the `docs` content collection (`docsLoader` + `docsSchema`)
- `site/package.json` — npm toolchain, pinned exact versions for `astro` and `@astrojs/starlight`

`site/` has its own Node/npm toolchain and is **excluded from `deno fmt` and `deno lint`**
(`deno.json`). Deno tooling walking `site/node_modules` makes `deno fmt` hang, which is why the
exclusion exists — do not remove it.

## Working rules

- Run the site with `deno task docs:dev`, build with `deno task docs:build`. Both delegate to npm in
  `site/`. `deno task docs:install` runs `npm ci`.
- Every page needs frontmatter with `title` and `description`. The build fails without `title`.
- Do **not** write an H1 or a hand-maintained "Contents" list in a page. Starlight renders the title
  from frontmatter and generates the table of contents.
- Internal links must include the base path: `/denex-network-manager/reference/cli/`. The site is a
  GitHub Pages _project_ site, so `base` is set and Astro does not rewrite bare absolute links in
  Markdown.
- Adding a page means adding it to the `sidebar` in `site/astro.config.mjs`. Nothing is
  autogenerated — the sidebar is explicit so ordering is controlled.
- Runtime URLs like `http://localhost:5082` belong in backticks, not as bare autolinks. The link
  validator treats a bare `localhost` URL as a broken internal link.

## Critical gotchas

- **The build validates links.** `starlight-links-validator` fails the build on any broken internal
  link or missing heading anchor. This runs on PRs too, so a bad cross-reference blocks merge. That
  is intentional; do not disable it to make a build pass.
- **Mermaid needs `astro-mermaid` ordered before `starlight`** in `integrations`. Otherwise
  Expressive Code claims ```mermaid fences first and renders them as ordinary highlighted code.
  There are currently 7 diagrams, all in `how-it-works/architecture.md`.
- **Pin `astro` and `@astrojs/starlight` exactly.** Starlight makes breaking config changes in minor
  releases — `social` became an array in 0.33, and labelled `autogenerate` sidebar groups were
  removed in 0.39. Read the Starlight changelog before bumping, and re-run the build.
- **`site/package-lock.json` must only contain `registry.npmjs.org` URLs.** This is a public repo,
  and a private npm mirror configured in `npm config get registry` gets baked into every `resolved`
  field by `npm install`. That both leaks internal hostnames and breaks `npm ci` in GitHub Actions,
  which cannot reach the mirror. After any dependency change, check:

  ```sh
  grep -c 'registry.npmjs.org' site/package-lock.json   # should equal the package count
  grep -c 'artifactory\|drwholdings' site/package-lock.json  # must be 0
  ```

  If the mirror leaked in, rewrite the prefix to `https://registry.npmjs.org/` — `integrity` hashes
  are content hashes and stay valid, and `npm ci` still resolves through whatever registry is
  locally configured. `deno.lock` has the same hazard; commit `265f45a` fixed it there once already.
- **Content here is canonical, not copied.** `docs/dev-stack-guide.md` and
  `docs/localnet-architecture.md` were moved into this tree, not duplicated. Do not reintroduce
  copies under `docs/`.
- Facts on this site are user-visible. Verify API claims against `src/` before publishing them — a
  prior version of the dev-stack guide taught a reuse recipe that could not work, because
  `fromInstanceId` is an existence check rather than a liveness check.

## Editing guidance

When you change CLI flags, config schema fields, or ports, update the corresponding reference page
in the same change:

| Change                             | Update                                               |
| ---------------------------------- | ---------------------------------------------------- |
| `src/cli/` commands or flags       | `site/src/content/docs/reference/cli.md`             |
| `src/schemas/localnet-config.ts`   | `site/src/content/docs/reference/configuration.md`   |
| `src/utils/ports.ts`               | `site/src/content/docs/reference/ports.md`           |
| `src/sdk/` public surface          | `site/src/content/docs/guides/sdk.md`                |
| Container layout, auth, onboarding | `site/src/content/docs/how-it-works/architecture.md` |

Regenerate CLI flag tables from the CLI itself (`deno task cli <command> --help`) rather than from
memory or from `README.md`.
